Your CATA Wallet

Check your CATA balance, send tokens, or approve a specific amount for a Catalyst action. Token approvals allow the named contract to spend only the amount you enter.

— CATA
Enter the amount as you normally write it (for example, 1.5 CATA). The app converts it to the token’s 18-decimal format.
Token writes are restricted to the protocol admin / reward controller per the deployed contract.

Your NFT Staking

Stake NFTs from a verified collection to earn rewards under the contract rules. You can stake for a 90-day term or choose permanent staking, which has a longer withdrawal restriction. Review the confirmation carefully before signing. Batch limit: 20 NFTs.

Staking requires the collection to be verified in the Registry and the staking contract approved for the token IDs.

Register an NFT Collection

Register your NFT collection so it can go through Catalyst’s verification process. The current registration fee is 100 CATA, split according to the protocol rules. Verification may take time and is not guaranteed.

Before registering, open CATA Token and approve the Registry contract to spend 100 CATA. Use the Registry contract address as the spender. Registration requires a valid NFT collection address and a collection information link. Registration does not guarantee verification.
The Registry exposes no escrow-refund function; expired escrow is not refunded by this interface.

Voting Snapshot Checks

This advanced area checks the voting records used by Governance. Most users do not need to use it directly. Turn on Advanced Details to enter technical proof information.

Publishing is routed through CatalystGovernance.publishSnapshot(): CatalystSnapshotVerifier.publishSnapshot() is governance-only, so a direct call from this page always reverts with Unauthorized.
Authorization to record against: write = verifier.publishSnapshot is msg.sender == governance; the Governance wrapper is msg.sender == snapshotPublisher and rejects sourceBlock >= block.number. revoke = verifier.revokeSnapshot is msg.sender == governance || guardianCouncil; CatalystGovernance has no forwarding function, so revocation is only reachable through a Guardian recovery proposal whose calldata is revokeSnapshot(...).

Community Decisions

Review a proposal, check whether your wallet is eligible to vote, then choose For, Against, or Abstain. Proposal creation and voting require a valid finalized snapshot and proof data. Technical proof fields are available in Advanced Details.

Proposals require a finalized verifier snapshot and a valid Merkle proof. Do not submit until the snapshot publisher and treasury are configured.

Catalyst Treasury

View the treasury balance, spending limits, and payment proposal status. Payments are made only through an approved Governance proposal; users cannot send money directly from this page.

No direct Treasury write is exposed: every write below is a read. Payments are proposed as Governance proposals of kind TreasuryPayment.
Governance lifecycle: createTreasuryProposal (registers payment, checks 10% single-payment cap) → vote → queueProposal (quorum + majority, 48h timelock) → executeProposal (calls treasury.executePayment, applies 20% rolling-window cap).

Catalyst Security

This panel reads the actual Guardian contract. Security actions are restricted to the roles and approval rules enforced on-chain. A normal-looking page does not mean the protocol is unlocked or risk-free.

Only active guardians can propose/approve. The guardian ABI in this build is generated from core_baseline/CatalystGuardian.sol.
